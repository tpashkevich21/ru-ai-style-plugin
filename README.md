# Humanizer – очеловечивание текста

Переписывает текст, который звучит как сгенерированный ИИ, чтобы он воспринимался как написанный человеком, сохраняя исходный смысл. Основан на статье Википедии [«Признаки текста, написанного ИИ»](https://en.wikipedia.org/wiki/Signs_of_AI_writing).

Эта версия подготовлена для **Codex** и **OpenCode**, которые загружают навыки (Agent Skills) из папки навыка. Метод редактирования не отличается от оригинальной версии Humanizer 3.1.0. Изменены только структура пакета и инструкции по установке.

Изменения каждого участника сразу отображаются у другого. Функция доступна бесплатно на всех тарифах.

Humanizer редактирует текст для людей. Обход детекторов ИИ не является целью, и детекторы по-прежнему распознают большую часть результатов его работы.

## Установка

Папка навыка должна называться строго `humanizer` и содержать файл `SKILL.md` непосредственно в корне.

**Установка на уровне пользователя** – общая для Codex и OpenCode:

```text
%USERPROFILE%\.agents\skills\humanizer\
```

Установка через PowerShell:

```powershell
$dest = "$env:USERPROFILE\.agents\skills\humanizer"
New-Item -ItemType Directory -Force -Path $dest | Out-Null
Copy-Item -Recurse -Force ".\humanizer\*" $dest
```

Если навык не появился в списке, перезапустите помощника или начните новый сеанс.

**Установка на уровне проекта:** разместите ту же папку внутри репозитория по пути `.agents/skills/humanizer/`. Оба инструмента обнаруживают навыки проекта в этой папке.

## Использование

Достаточно сформулировать запрос обычным языком:

```text
Очеловечь этот текст: [вставьте текст]
```

Чтобы переписать содержимое файла, укажите его путь:

```text
Очеловечь текст в файле docs/launch-post.md
```

Чтобы адаптировать текст под ваш стиль, добавьте пример собственного письма или другого текста. Этот образец имеет приоритет над правилами распознавания шаблонов, включая правило использования тире.

## Что возвращает навык

- **Вставленный текст.** Предлагает переписанный вариант, краткий список оставшихся характерных шаблонов и итоговую версию.
- **Режим работы с файлом.** В файл записывается только окончательный текст. Код, команды, пути, метаданные YAML, данные и адреса ссылок остаются без изменений.
- **Встроенный режим.** Если другой процесс вызывает навык для подготовки сообщения коммита или документа, возвращается только окончательный текст.

## Принцип работы

Языковая модель выбирает наиболее вероятное продолжение текста, поэтому по умолчанию использует формулировки, подходящие максимально широкой аудитории. Человек пишет для конкретного читателя и по конкретной теме. Каждый из перечисленных ниже шаблонов представляет собой один из вариантов такого поведения модели.

Навык сначала выявляет наиболее заметные признаки ИИ-текста, начиная с самых выраженных. Затем готовит новую версию, не считая исходную структуру обязательной. После этого проверяет, не были ли добавлены или потеряны факты, и формирует окончательный текст.

Если для корректной переработки не хватает информации, навык запрашивает её у автора, а не придумывает самостоятельно.

## Проверка пакета

Для запуска скрипта `scripts/validate-skill.py` требуется Python версии 3.10 или новее. Дополнительные зависимости не нужны.

Команда для PowerShell:

```powershell
python scripts\validate-skill.py .
```

Скрипт проверяет:

- корректность метаданных YAML в начале файла;
- название папки;
- длину описания;
- нумерацию шаблонов;
- внутренние ссылки и перекрёстные ссылки;
- соответствие названий шаблонов в README;
- ограничение на количество слов.

## Что изменено для Codex и OpenCode

- В корне папки находится один файл `SKILL.md`, который загружают оба инструмента.
- Инструкции по установке и использованию адаптированы под общий путь `.agents/skills`.
- Удалены манифесты плагинов Claude и Cursor, а также руководство по сопровождению репозитория. Они относятся к исходной структуре пакета и не используются Codex и OpenCode.
- Скрипт `scripts/validate-package.py` заменён на `scripts/validate-skill.py`, который проверяет структуру папки навыка, а не манифесты плагинов.

Тексты шаблонов, нумерация, примеры и инструкции по редактированию не изменялись.

Исходный проект: [blader/humanizer](https://github.com/blader/humanizer).

## Ограничения

- Запуск навыка зависит от самого инструмента, а не от содержимого пакета. Единственный общий для обоих инструментов сигнал для определения назначения навыка – поле `description`.
- Проверялась структура папки навыка, но не выполнялись реальные задачи по редактированию текста отдельно в каждом инструменте.
- Обход детекторов ИИ не входит в задачи навыка.
